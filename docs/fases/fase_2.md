# Fase 2 — Extração de Snippets e Cálculo de Métricas

## Objetivo

A Fase 2 é o **extrator estrutural** do pipeline. Sua responsabilidade é varrer o
repositório clonado, parsear cada arquivo PHP em uma AST (Abstract Syntax Tree) e
produzir uma lista de "snippets" — unidades semânticas (classes, traits, métodos,
funções) — cada um acompanhado de um conjunto de métricas quantitativas calculadas
a partir do próprio AST. Esses snippets são a granularidade de trabalho de todas as
fases seguintes: a Fase 3 mapeia findings de análise estática a snippets; a Fase 4
mostra um snippet por vez ao anotador; a Fase 5 monta o dataset linha-a-linha com
um registro por snippet.

Em uma frase: a Fase 2 transforma "um repositório PHP arbitrário" em "uma lista
estruturada de unidades de código, cada uma com tamanho, complexidade e cognitividade
medidas".

Script: `scripts/fase2_extrair_snippets.php` (PHP 8.1+, depende de
[`nikic/php-parser`](https://github.com/nikic/PHP-Parser) `^5.0` instalado via
Composer em `config/`).

---

## Tipos de snippet extraídos

O extrator reconhece quatro tipos de unidade, com a lógica em
`SnippetExtractorVisitor` e `MethodExtractorVisitor`:

| Tipo        | Origem AST                               | Campos específicos no JSON              |
|-------------|------------------------------------------|-----------------------------------------|
| `class`     | `Node\Stmt\Class_` (não puramente abstr.)| `num_methods`, `num_properties`, `parent_class`, `implements`, `is_abstract` |
| `trait`     | `Node\Stmt\Trait_`                       | `num_methods`, `num_properties`         |
| `function`  | `Node\Stmt\Function_` (top-level)        | `num_parameters`, `return_type`         |
| `method`    | `Node\Stmt\ClassMethod` (qualquer visib.)| `class_name`, `method_name`, `num_parameters`, `return_type`, `visibility`, `is_static` |

`interface` e classes 100% abstratas (sem **nenhum** método com corpo) são
**ignoradas** via `isDeclarationOnly()` — não há código real para analisar.

> Os métodos são extraídos *além* de aparecerem dentro do snippet de classe. Isso é
> proposital: a Fase 3 precisa atribuir findings tanto à granularidade fina (método)
> quanto à granular grossa (classe). Um finding numa linha que cai dentro de um
> método x dentro da classe X **é atribuído aos dois snippets**.

## Filtros aplicados (qualidade da amostra)

Nem todo arquivo nem toda unidade entra no dataset. Cinco camadas de filtro:

### 1. Diretórios excluídos por path (regex)

```
config/, migrations/, routes/, factories/, seeders/,
database/(migrations|seeders|factories)/,
vendor/, node_modules/, tests?/, storage/,
bootstrap/cache/, public/
```

E mais: `*.blade.php` (templates de view, não código PHP "real").

Justificativa: estes diretórios contêm código gerado, fixtures, ou
infraestrutura de framework cuja "smell" é irrelevante para a metodologia.

### 2. Código gerado automaticamente (`isGenerated()`)

Verifica os primeiros 500 caracteres do arquivo procurando marcadores típicos:

- `auto-generated`, `autogenerated`
- `do not edit`, `generated by`
- `this file is generated`
- `@generated`

Arquivos com qualquer um destes são descartados inteiros.

### 3. Erros de parsing (try/catch)

Se `nikic/php-parser` jogar exceção em algum arquivo (PHP malformado, sintaxe
exótica), o arquivo é pulado e o contador `parse_errors` no metadata é
incrementado. **Não aborta** a fase.

### 4. Classes/interfaces apenas declarativas (`isDeclarationOnly()`)

- Toda `interface` → sempre ignorada (não tem corpo).
- `abstract class` cujos métodos são **todos** abstratos → ignorada (idem).
- `abstract class` com pelo menos um método concreto → entra no dataset
  (a parte concreta tem comportamento mensurável).

### 5. Filtro por métricas (limiares de "código trivial")

Após calcular as métricas, snippets com:

- `loc_executable <= 3` (3 linhas executáveis ou menos), **OU**
- `cyclomatic_complexity < 2`

são descartados. Isso elimina getters/setters triviais, métodos vazios, classes
de uma linha, etc. A intenção é evitar "ruído estatístico" — snippets onde não
existe espaço para code smell de fato.

## Métricas calculadas

Todas as métricas são implementadas **à mão**, sem libs externas (restrição
metodológica registrada em `AGENTS.md`). São quatro famílias:

### 1. LOC (Lines of Code) — `calculateLOC()`

Conta as linhas do código serializado pelo `PrettyPrinter` do nikic/php-parser:

- `loc_total`: total de linhas (incluindo branco e comentário).
- `loc_blank`: linhas em branco.
- `loc_comment`: linhas de comentário (`//`, `#`, `/* */`, `/** */`).
- `loc_executable`: `loc_total - loc_blank - loc_comment`.

Detecta corretamente comentários multi-linha mantendo estado `inBlock`.

### 2. Complexidade Ciclomática — `CyclomaticComplexityVisitor`

Implementa a definição clássica de McCabe: complexidade base 1 + 1 para cada
ponto de decisão. Pontos contados (visitor na AST):

- Statements: `if`, `elseif`, `case`, `catch`, `for`, `foreach`, `while`, `do-while`.
- Expressões: ternário (`?:`), null coalesce (`??`), `&&`, `||`, `and`, `or`.
- `match` arm com N condições → soma N.
- Operadores null-safe: `?->`, `?->prop`.

`else` puro **não** soma (já está coberto pelo `if` correspondente).

### 3. Profundidade de Aninhamento — `NestingDepthVisitor`

Visitor com contador `currentDepth` que sobe ao entrar em estruturas que aninham
escopo e desce ao sair. Estruturas consideradas:

- Controle: `if`/`elseif`/`else`, `for`, `foreach`, `while`, `do`, `switch`, `try/catch`.
- Funções inline: `Closure` (`function() { }`) e `ArrowFunction` (`fn() => ...`).

Retorna o **máximo** observado em qualquer ponto da AST do snippet. Threshold
informal de "deep nesting" começa em ≥ 4.

### 4. Métricas de Halstead — `HalsteadCalculator`

Análise de tokens via `token_get_all()` do PHP, separando em **operadores** e
**operandos**. Lista de ~60 operadores (aritméticos, lógicos, atribuição
composta, comparação, bitwise, escopo `::`, `->`, palavras-chave como `new`,
`clone`, `instanceof`, controle de fluxo, etc.) e detecção de operandos por
tipo de token (`T_VARIABLE`, `T_LNUMBER`, `T_DNUMBER`, strings, identificadores
nomeados).

A partir das contagens (`n1`, `n2`, `eta1`, `eta2`) calcula:

| Métrica                 | Fórmula                                       | Interpretação                                  |
|-------------------------|-----------------------------------------------|-----------------------------------------------|
| `halstead_vocabulary`   | `eta1 + eta2`                                 | tamanho do "alfabeto" do código               |
| `halstead_length`       | `n1 + n2`                                     | total de tokens                                |
| `halstead_volume`       | `length * log2(vocabulary)`                   | tamanho cognitivo (bits)                       |
| `halstead_difficulty`   | `(eta1 / 2) * (n2 / eta2)`                    | esforço para escrever/compreender              |
| `halstead_effort`       | `volume * difficulty`                         | esforço total estimado                         |
| `halstead_time`         | `effort / 18`                                 | tempo em segundos (constante de Halstead)      |
| `halstead_bugs`         | `volume / 3000`                               | número esperado de defeitos                    |

Se o snippet for trivial demais (`vocabulary == 0`, `eta2 == 0` ou `length == 0`),
todas as métricas Halstead viram `0` (evita divisão por zero).

## Fluxo interno

```
1. Localizar autoload do Composer  ←  config/vendor/autoload.php
2. Validar args  ←  argv[1] = repo_dir
3. Detectar nome do repo  ←  basename(repo_dir) ou composer.json:name
4. Listar todos *.php recursivamente  ←  RecursiveIteratorIterator
5. Para cada arquivo:
     5.1. Excluir por path (regex)
     5.2. Ler conteúdo
     5.3. Excluir se for código gerado
     5.4. Parsear com nikic/php-parser → AST
          (se falhar: parse_errors++, próximo arquivo)
     5.5. Rodar SnippetExtractorVisitor  → classes/traits/functions
     5.6. Rodar MethodExtractorVisitor   → métodos com class_name
     5.7. Para cada snippet candidato:
            ignorar se for declaração pura
            calcular LOC, CC, NestingDepth, Halstead
            descartar se loc_executable<=3 ou cc<2
            atribuir snippet_id sequencial (SNIPPET_NNNN)
            empurrar para allSnippets
6. Detectar commit hash via .git/HEAD + ref interno
7. Serializar:
     output/fase2/snippets_com_metricas.json
     output/fase2/snippets_com_metricas.csv
```

A varredura é **single-pass linear** sem paralelização — em repositórios grandes
(>5 mil arquivos PHP) demora alguns minutos, mas a memória se mantém estável
(o garbage collector do PHP libera AST entre arquivos).

### Campos consumidos pelas próximas fases

- **Fase 3** (`fase3_consolidar.py`): `snippet_id`, `file_path`, `snippet_type`,
  `snippet_name`, `start_line`, `end_line`, `loc_executable`, `cyclomatic_complexity`.
  Os outros campos vão "junto pelo passeio" mas não são lidos pelo consolidador.
- **Fase 4** (`fase4_preparar_interface.py`): praticamente **tudo**. O painel
  direito da interface mostra todas as métricas; o painel esquerdo mostra `code`
  re-extraído do arquivo via `start_line..end_line` para garantir alinhamento
  com smells reportados pela Fase 3.
- **Fase 5** (`fase5_validar_dataset.py`): junta cada snippet com seu pré-rótulo
  da Fase 3 (e opcionalmente com a anotação humana da Fase 4) para montar o
  dataset final.

### Detecção do commit hash

Pré-existe a Fase 2 a leitura de `.git/HEAD`:

- Se HEAD apontar para `ref: refs/heads/main`, lê `.git/refs/heads/main`.
- Se HEAD for um SHA direto (detached HEAD), usa esse valor.
- Se nada disso funcionar (clone sem `.git/`), grava `"unknown"`.

> Note: o `git clone --depth 1` do Compose mantém o `.git/` mínimo, então o
> commit hash aparece corretamente. Se você bind-mountar um diretório sem
> `.git/`, o campo virará `"unknown"` — não é erro, só informação ausente.

### CSV achatado

29 colunas: identidade do snippet (id, repo, file, tipo, nome, linhas), todas
as métricas LOC/CC/Nesting/Halstead, dados estruturais (num_methods,
visibility, etc.) e um `code_preview` truncado em 200 caracteres com quebras
de linha viradas em espaço. Pensado para abrir direto em Excel/Pandas sem
ter que processar o JSON aninhado.

## Execução prática

A Fase 2 depende do Composer ter instalado as deps em `config/vendor/`. No
Docker isso já está feito durante o `make build`. Comandos típicos:

```bash
# Pipeline completo (Fase 1 → 2 → 3 → 4 → 5)
make run REPO=FakerPHP/Faker

# Só a Fase 2 (Fase 1 já rodou; clona se necessário)
docker compose --profile fase2 up fase2

# Manual sobre um repo já clonado
docker compose run --rm shell php scripts/fase2_extrair_snippets.php repos/FakerPHP_Faker

# Caminhos customizados de saída
docker compose run --rm shell php scripts/fase2_extrair_snippets.php \
    repos/FakerPHP_Faker /tmp/custom.json /tmp/custom.csv
```

O bloco do Compose (`docker-compose.yml`, linhas 108–122):

1. Lê `output/fase1/repositorio_metadata.json` para obter `repo_name` e
   `github_url`.
2. Faz `git clone --depth 1 <url>.git repos/<owner>_<repo>` se ainda não
   houver clone (cache local).
3. Roda `php scripts/fase2_extrair_snippets.php repos/<owner>_<repo>`.

Diferenças significativas (>10–15%) entre runs do mesmo commit indicam:

1. Versão diferente de `nikic/php-parser` (mudança em quais nodes são
   suportados na nova versão do PHP).
2. Filtros de path ou thresholds (LOC, CC) modificados sem ajuste.
3. Mudança do binário PHP em si (PHP 8.2 vs 8.3 detecta tokens levemente
   diferentes em código com sintaxe muito nova).

## Contrato com as fases anteriores e seguintes

- **Entrada exigida:**
  - `output/fase1/repositorio_metadata.json` (lido pelo wrapper Compose para
    montar o `git clone` — o script PHP em si só precisa do diretório do repo).
  - O próprio repositório clonado em `repos/<owner>_<repo>/`.
- **Saída exigida pelas próximas fases:**
  - `output/fase2/snippets_com_metricas.json` é a fonte da verdade. Todo o
    resto do pipeline gira em torno dele.

Sem este JSON, a Fase 3 não tem onde mapear findings e a Fase 4 não tem o que
mostrar ao anotador. Por isso a Fase 2, junto com a 1, é **obrigatória**.

## Pontos de atenção e armadilhas conhecidas

1. **Bug corrigido em 2026-05-13.** `fprintf(STDOUT|STDERR, "%...")` quebra no PHP 8
   se a string de format tiver `%` literal não-escapado. Trocado por `fwrite()`
   onde necessário. Ver `AGENTS.md` (seção "Bugs corrigidos").
2. **Snippets duplicados intencionais.** Um método aparece como `method`
   (`Classe::metodo`) **e** está contido no `class` da mesma classe. Não é bug —
   é a base para a Fase 3 atribuir findings nos dois níveis de granularidade.
3. **Pretty-printer do nikic.** O `code` salvo é o **reserializado** pelo
   pretty-printer, não o texto original. Por isso a Fase 4 re-extrai do arquivo
   original via `start_line..end_line` para garantir alinhamento exato com os
   findings da Fase 3 (que reportam linhas do arquivo original).
4. **`loc_total` × pretty-print.** Como o `code` é reserializado, `loc_total`
   pode diferir levemente de `end_line - start_line + 1`. Não use uma métrica
   para checar a outra — são fontes diferentes.
5. **Filtro de diretórios.** Os padrões são regex case-insensitive com `#`
   como delimitador. Adicionar exclusão exige preservar o formato (ex.:
   `'#/examples?/#i'`). Quebrar isso silenciosamente faz a Fase 2 incluir
   código que não deveria estar no dataset.
6. **Limiares LOC/CC.** `loc_executable > 3` e `cc >= 2` são valores
   **metodológicos**. Diminuir esses limiares enche o dataset de getters/setters
   e distorce a distribuição (muito mais snippets `clean` artificiais).
   Aumentá-los reduz drasticamente o N. Modificar exige justificativa documental.
7. **Halstead em código com strings interpoladas.** Strings com `${var}` ou
   `"$var"` são tokenizadas de forma não-trivial pelo `token_get_all` —
   `T_ENCAPSED_AND_WHITESPACE` aparece como operando, o que pode inflar `n2`
   em arquivos com muita string. Comportamento conhecido, dentro da definição
   clássica de Halstead.
8. **Commit hash com `clone --depth 1`.** Funciona: o `.git/HEAD` ainda aponta
   para o ref correto. Mas você não tem histórico — se quiser navegar
   commits anteriores, vai precisar refazer o clone sem `--depth`.
9. **Memória em repos enormes.** Em projetos com >20 mil arquivos PHP, o PHP
   pode estourar `memory_limit` durante o parsing de arquivos muito grandes.
   Solução: rodar com `php -d memory_limit=2G scripts/fase2_extrair_snippets.php`.
